# 5. Контролируемая таблица заявок

Меер Джонатан · ОП.03 · 24.11.2026 · группа не указана

В leads.xlsx создан лист leads с девятью заголовками, закреплённой строкой и списком new / in_progress / done / rejected. Отдельные правила выделяют неполную запись и повторный request_id.

Приёмник Code.gs проверяет структуру таблицы, обязательные поля, email и формат идентификатора. Проверка дубля и запись выполняются под одной блокировкой. Время задаёт сервер. Статус новой заявки всегда new.

| Проверка | Ожидаемый результат |
|---|---|
| Прямой вход | direct / none / not_set |
| ?utm_source=telegram&utm_medium=social&utm_campaign=lesson07 | telegram / social / lesson07 |
| Повтор POST с тем же ID | duplicate_request_id, дополнительная строка не создаётся |
| Пустое имя | Браузер блокирует отправку; сервер также проверяет обязательные поля |
| Ввод finished | Таблица отклоняет значение |
| Смена статуса через список | new → in_progress → done |

Для подключения предназначены SPREADSHEET_ID в Code.gs и action в site/contacts.html. Публикация Web App и две записи в личной Google Таблице не подтверждены.

Подготовлено с помощью ИИ.
